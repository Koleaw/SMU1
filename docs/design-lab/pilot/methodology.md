# Методика пилотного исследования

## Цель и границы

Пилот проверяет не «похожесть» сайтов, а пригодность доказательного визуального исследования для будущего редизайна СМУ-1. Основной сайт СМУ-1 не изменяется. Контекст применимости взят из `docs/MASTER_SPEC.md` и текущей структуры проекта только в режиме чтения.

Исследование отвечает на пять практических вопросов:

1. Можно ли получить реальный клиентский рендер, а не HTML или поисковый фрагмент.
2. Можно ли надежно сохранить desktop/mobile-состояния.
3. Можно ли связать визуальное наблюдение с URL, PNG и измерениями DOM.
4. Различимы ли подходы пяти сайтов на уровне композиции и сценариев.
5. Достаточна ли надежность процесса для расширения выборки.

## Выборка и страницы

| Сайт | Роль в пилоте | Исследованные типы |
|---|---|---|
| Foster + Partners | архитектурная подача и проектный архив | home, Projects, доступный project detail, Studio, mobile home/menu |
| Vestre | каталог уличной мебели и связь с references | home, Products, Seating, STOOP bench, References, reference detail, mobile home |
| mmcité | предметный каталог и проекты городской мебели | home, Products mega-menu, категория, Vera, References, reference detail, mobile home/menu; отдельно проверен пустой `/products` route |
| Skanska | строительная экспертиза, масштаб и доверие | home, Construction, Projects, Crossrail project detail, About, mobile home |
| Linear | типографика, темные поверхности и продуктовая иерархия | home, Features, Plan, mobile home |

Недоступная заданная страница не заменялась без фиксации. Для Foster заданный Apple Park URL и About отмечены как неуспешные; доступный project detail и Studio использованы только с явным указанием fallback.

## Инструменты

- встроенный web search/open: поиск актуальных официальных URL и независимая текстовая перепроверка;
- PowerShell/curl: HTTP-диагностика и редиректы;
- установленный Chrome 149: независимый нативный рендер и обход ложного отрицательного результата Vestre checkpoint;
- уже кэшированный Playwright 1.60 + Chromium 148: управление viewport, ожидание загрузки, screenshots, DOM и computed styles;
- локальный `view_image`: визуальная проверка PNG в момент сбора;
- исследовательский helper `_research-browser.cjs`: временная воспроизводимая автоматизация внутри разрешенного каталога.

Установка npm-пакетов, браузеров и любых зависимостей не выполнялась.

## Режим захвата

### Desktop

- viewport: `1440 × 1000` CSS px;
- device scale factor: `1`;
- для статически надежных страниц: full-page PNG плюс отдельный viewport первого экрана;
- для динамических reveal/lazy страниц Vestre: первый экран `1440 × 1000` и отдельные viewport-зоны после контролируемой прокрутки.

### Mobile

- viewport: `390 × 844` CSS px;
- mobile user agent, `isMobile: true`, touch input;
- full-page и первый экран там, где full-page корректно удерживал контент;
- у Vestre: первый экран и отдельные прокрученные зоны из-за viewport-dependent reveal.

### Ожидание готовности

Для каждой страницы выполнялись:

1. `DOMContentLoaded`, затем `load`; `networkidle` ожидался с конечным таймаутом.
2. Ожидание `document.fonts.ready`.
3. Пошаговая прокрутка для lazy media.
4. Проверка `img.complete`, natural dimensions и broken image count.
5. Возврат к началу страницы и стабилизационная пауза.
6. Снятие screenshot и проверка PNG dimensions.

Cookie wall принимался фактической кнопкой (`Allow all`, `Accept all`, `Yes, I agree` и аналогичной). Действие сохранялось в capture-реестре. Если wall, ошибка, skeleton или redirect placeholder оставались на снимке, страница не считалась успешно исследованной.

## Собираемые доказательства

На каждый рендер сохранялись:

- requested и final URL;
- дата/время просмотра в ISO и локальное время в отчетах;
- title, тип страницы, HTTP document responses и navigation errors;
- consent action, request failures и console errors;
- viewport и document dimensions;
- размеры/позиции header, main, H1, крупных media и grid-контейнеров;
- computed font family, size, weight, line height, colors, background, position, radius, shadow;
- loaded/broken image count, video count и число активных CSS/Web Animations;
- full-page, viewport и при необходимости zone PNG.

Точные значения приводятся только там, где они были измерены. В остальных случаях используется качественное описание без псевдоточной оценки.

## Правило анализа A–D

Каждое существенное наблюдение в site-отчетах разложено на четыре части:

- **A. Подтвержденный факт:** что видно в PNG/DOM или измерено.
- **B. Аналитическая интерпретация:** какое впечатление или поведенческий эффект это может создавать.
- **C. Возможная адаптация:** как перенести принцип в сценарии СМУ-1 без копирования реализации.
- **D. Ограничение:** контентный, коммерческий, технический или организационный риск.

Существенный факт сопровождается URL, именем PNG, измерением или конкретным DOM-элементом. Поисковые сниппеты не использовались как визуальное доказательство.

## Сравнение и применимость

Сравнение проводится по темам hero, navigation, typography, whitespace, photography, dark usage, cards, catalog/product/project pages, trust, CTA, motion и mobile. Для выборки из пяти сайтов фиксируются только:

- повторяющиеся паттерны;
- редкие решения;
- противоречия;
- гипотезы, требующие более широкой проверки.

Статистические формулировки и обобщения вида «лучшие сайты используют» исключены.

Применимость оценивается относительно утвержденных сценариев СМУ-1: каталог, проектные услуги, выполненные объекты и получение заявки. Приоритет B2B, коммерческая цель загрузки сварочного цеха, честные цены и запрет выдуманных кейсов/цифр считаются обязательными ограничениями.

## Ограничения методики

- Это разовый снимок живых сайтов, а не longitudinal study.
- Motion подтверждался видимым поведением и `document.getAnimations()`, но не записывался в видео и не разбирался покадрово.
- Не выполнялись Lighthouse, Core Web Vitals, accessibility audit, keyboard-only audit и тестирование форм до отправки.
- Mobile подробно исследован на главных страницах; внутренние mobile-шаблоны не покрыты системно.
- Не проверялись все фильтры, download flows, авторизация, карта и внешние сервисы.
- Сильные визуальные приемы Foster/Vestre/Skanska зависят от дорогого фото/видеоконтента; перенос без такого контента оценивается отдельно.
