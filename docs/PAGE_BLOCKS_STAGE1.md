# Структурные блоки страниц (`pageBlocks`) в H6

Этот документ заменяет устаревшую инструкцию пилота Stage 1. `pageBlocks` больше не относится только к странице «Навесы» и не редактируется через Pages CMS.

## Текущий контракт

`pageBlocks` — опциональный массив структурированных секций в content records. Поле используется в нескольких `product-sections`, `services` и `static-pages`; конкретный публичный шаблон определяет, какие типы секций действительно выводятся.

Каждый блок имеет как минимум:

- `type` — тип секции;
- `order` — порядок;
- `isActive` — видимость, если поле присутствует;
- типовые content/media/layout поля, разрешённые схемой;
- дополнительные legacy-поля, которые схема и транзакционный слой сохраняют без потерь.

Схема намеренно принимает строковый `type`: исторические шаблоны используют разные семейства блоков. Поэтому нельзя считать старый список из семи типов универсальным allowlist.

## Как редактировать

1. Запустите локальную админку и откройте нужную страницу/направление.
2. В группе **«Секции страницы»** откройте редактор `pageBlocks`.
3. Меняйте заголовок, текст, видимость и порядок только у секций, которые UI помечает поддерживаемыми текущим шаблоном.
4. Добавляйте секцию только из списка, предложенного самим редактором для этой template family.
5. Нажмите **«Сохранить на компьютере»** и проверьте точную локальную страницу.
6. Публикуйте preview отдельным действием после проверки.

При перемещении UI нормализует `order`. Выключенная секция сохраняется, но не должна выводиться там, где шаблон поддерживает `isActive`.

## Legacy и неподдерживаемые блоки

Если блок помечен **«Текущий сайт может не выводить»**, обычная форма не пытается угадывать его структуру. Значение показывается как техническая информация и сохраняется без изменений.

Не удаляйте и не пересоздавайте такой блок ради снятия предупреждения. Сначала разработчик должен сопоставить `type` с реальным renderer и добавить точное правило поддержки в content coverage registry.

## Что не является редактируемым дизайном

`pageBlocks` не даёт права вставлять произвольные HTML, JavaScript, CSS-классы, цвета или внешние embed-коды. Внешний вид контролируется публичными компонентами и разрешёнными schema fields. Изменение renderer/template — source release разработчика, а не content transaction владельца.

## Проверки перед публикацией

- порядок и видимость секций верны;
- текст и ссылки проверены;
- изображения выбраны из прошедших H6 media validation;
- локальная публичная страница действительно выводит изменённый блок;
- нет предупреждения о неподдерживаемом типе для редактируемой секции;
- сохранение завершилось локальной транзакцией до открытия publish plan.
