# Проверка регрессии добавления фотографий

Первая CI-проверка коммита `59f008f7cdef0bc11e62d916253a0f6bf82647c9` обнаружила реальную ошибку геометрии редактора. Это не объявлено случайным сбоем и не исправлялось повторным запуском без изменения кода.

В запуске `34539310858`, job `103078174591`, не прошли `bulk-media-queue`, `reload-recovery` и `bulk-media-stage-save`. Все 20 корректных файлов получили HTTP 201 при подготовке медиа. Два ответа HTTP 400 относятся к намеренно испорченному тестовому файлу и его повтору. После позднего исключения сценарий не вернул разрешение на эти ожидаемые ответы, поэтому отчёт дополнительно посчитал их ошибками HTTP.

Причину подтвердил отдельный Chromium-проход на изолированной копии текущего сайта. Публичное desktop-правило задавало `width:auto` контейнеру галереи. В редакторе этот же контейнер при отсутствии фотографии служит абсолютной областью «Добавить фотографии», внутри которой тоже находится абсолютная кнопка. Её ширина схлопнулась до нуля. Старый тест выбирал первый ненулевой media-binding и попадал в связанную карточку другого изделия, затем ожидал черновик исходного изделия.

| Фактическое измерение | Ширина × высота | Владелец binding |
| --- | --- | --- |
| Исходная область добавления фото | 0 × 412,58 px | `konteynernaya-ploshchadka-modul` |
| Следующая связанная карточка, выбранная старым тестом | 176 × 46 px | `konteynernaya-ploshchadka-zakrytaya` |
| Временное восстановление задуманной половинной ширины в диагностическом браузере | 687,5 × 412,58 px | `konteynernaya-ploshchadka-modul` |
| Окончательный исходный CSS при ширине canvas 1440 / 390 / 320 px | 220 × 50 px | `konteynernaya-ploshchadka-modul` |

Desktop-правило публичной галереи ограничено реальным дочерним компонентом: `:has(> .v2-product-gallery)`. После исключения редакторской области визуально обнаружен прежний каскад `width:100vw`. Поэтому собственные ширина, высота и нулевой внешний отступ закреплены через `!important` только в CSS редактора. Это не позволяет публичным правилам первого экрана переопределить размеры служебной кнопки.

Окончательная область компактна: максимум 220 × 50 px, на desktop не шире половины родительского контейнера. Она располагается справа внизу. При ширине до 980 px только первый экран без фотографии в редакторе получает 64 px нижнего пространства под кнопку. Это устраняет пересечение со ссылкой Telegram, выявленное на промежуточном мобильном проходе. Публичная страница и редакторские страницы с фотографией этого отступа не получают.

Сам acceptance-сценарий усилен: `no-photo-affordance` сохраняет фактические размеры, требует область не меньше 44 × 44 px, не шире половины родителя и точного владельца исходного изделия. Все три поиска media-binding для очереди, восстановления и сохранения теперь явно задают `ownerSlug`. Архитектура редактора, хранилище черновиков и API загрузки не перестраивались.

Завершающий Chromium-проход по фактическому source выполнен на ширинах iframe 1440, 390 и 320 px. Во всех трёх случаях область составляет 220 × 50 px; проверка пересечений с текстовыми строками заголовка, описания, цены, преимуществ и действий вернула пустой список. Шесть снимков первого экрана и кнопки после прокрутки лично просмотрены: длинный заголовок переносится, подпись кнопки читается, текст и действия не перекрыты. Настоящий клик на 320 px открыл окно массовой загрузки именно для «Контейнерная площадка Модуль» с полем выбора файлов; Escape закрыл окно. Файлы не добавлялись и не сохранялись.

Локально выполнены 11 тестов `visual-editor-acceptance.test.mjs`: 11 PASS. Геометрические диагностические проходы не сохраняли контент и не вызывали release-операции. Полный повтор CI и финальная проверка опубликованной версии на момент этой записи ещё ожидаются.

Доказательства вне репозитория: `E:/CodexTemp/smu1-owner-20260911/media-geometry.json`, `media-geometry-before.png`, `media-geometry-after.png`, `media-geometry-source-after.json`, `media-geometry-source-after.png`. Последние два файла показывают промежуточное исключение из публичного правила, а не окончательный UI-проход.

Окончательные доказательства в той же папке: `media-affordance-final.json` (`passed: true`), `media-affordance-final-{1440,390,320}-{hero,control}.png` и `media-affordance-final-dialog.png`. Все процессы изолированного браузера, Astro и API закрыты после проверки.

Отдельный CI-сбой проверки `beforeunload` локально не воспроизвёлся: исходный файл прошёл 9/9. Fixture дополнен подтверждением установленного обработчика, настоящего клика и sticky activation перед прежней проверкой отказа навигации. Чтение состояния не создаёт user gesture. Защита CDP не ослаблена; целевой браузерный тест прошёл 1/1 без пропуска (`beforeunload-readiness-target.log`). Причина исходного CI-сбоя не объявляется доказанной.

После ограничения публичного селектора и уточнения светлого клавиатурного контура выполнена сборка 229 страниц, затем штатная очистка недостижимых медиа. H5: 22/22, 420540767 байт, 4373 файла, одно прежнее мягкое предупреждение LCP благоустройства; бюджеты не менялись (`h5-ci-fix.json`). Статическая проверка с конфигурацией test и `/SMU1/`: 38/38, 107 маршрутов, 9296 ссылок, 15213 ссылок на медиа (`static-ci-fix-correct-env.log`). В публичных CSS отсутствуют селекторы области редактирования. 13 тестов acceptance/геометрии полноэкранной галереи прошли; они не заменяют повтор полного браузерного CI.

Адресный проход фокуса выявил два соседних дефекта. Специфичность общего правила галереи переопределяла светлый контур в «Волне» и «Портале»; дополнительное условие публичного контейнера устранило конфликт без `!important`. Во всех трёх движках повторно подтверждён белый контур 3 px на полноэкранных кнопках этих двух изделий. У навесов собственный переход цвета SVG-path запускался позже перехода контейнера: промежуточно получалась белая стрелка на белом фоне. Для активных полноэкранных кнопок сохранены светлая стрелка и тёмная нейтральная поверхность `#304151`. Окончательная сборка после этого изменения снова прошла H5: 22/22, 420541012 байт, 4373 файла (`h5-gallery-contrast.json`).

Завершающий повтор навесов прошёл в Chromium, Firefox и WebKit: после отсутствия активных переходов во всём SVG-поддереве реальный stroke белый, фон `#304151`, контраст 10,50:1, контур 2 px, Escape возвращает фокус. Снимки просмотрены (`final-gallery-focus/report.json` и PNG). Равные половины «Волны» при 1366/390 px подтверждены во всех трёх движках; обе CTA на тематических панелях проверены настоящим Tab в Chromium/Firefox.

У установленного Windows WebKit обычный Tab и Alt+Tab пропускают ссылки. Это отдельно воспроизведено на простом HTML с двумя ссылками, input и button без кода/стилей СМУ-1. Поэтому три сценария достижения hero-ссылок через Tab не обозначены успешными. Их CSS-контур дополнительно проверен на «Волне» программной установкой фокуса после клавиатурного ввода: белый, 2 px, `:focus-visible`. Этот способ не выдан за достижение ссылки через Tab. Управление настоящими кнопками галереи, поиска и меню в WebKit проверено отдельно.
