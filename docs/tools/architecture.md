# Архитектура строительных инструментов

Состояние реализации: 29.09.2026. Раздел работает в статической сборке Astro. Вычисления и проекты посетителя остаются в браузере; публичный сервер расчётов не требуется.

## Маршруты и загрузка

| Страница | Код вычислений |
| --- | --- |
| `/instrumenty/metal/` | `src/tools/calculations/metal.mjs` |
| `/instrumenty/raskroy/` | `src/tools/calculations/cutting.mjs` |
| `/instrumenty/fundament/` | `src/tools/calculations/foundation.mjs` |
| `/instrumenty/ograzhdenie/` | `src/tools/calculations/fence.mjs` |
| `/instrumenty/plitka/` | `src/tools/calculations/tile.mjs` |
| `/instrumenty/maf/` | `src/tools/calculations/maf.mjs` |
| `/instrumenty/zdanie/` | `src/tools/calculations/building.mjs` |

`src/pages/instrumenty/index.astro` строит архив из коллекции `tools`, сортируя записи по `order`. `[tool].astro` создаёт ровно семь самостоятельных страниц. `ToolPage.astro` выводит заголовок, описание, пример, методику, ограничения и контакты при статической сборке. Без JavaScript остаётся это содержание и сообщение о необходимости JavaScript для вычислений.

`src/tools/app.mjs` управляет общей формой, папкой проектов и состоянием результата. Адаптер текущего инструмента загружается через ленивый `import.meta.glob`; тестовые модули исключены. Адаптер связывает чистый расчёт с полями, SVG и таблицами. Код других вычислительных модулей не нужен карточке товара. Печатный документ загружается отдельным динамическим импортом `src/tools/core/print.mjs` после команды печати. Раскрой выполняется через Worker; отмена и ограничения задачи находятся в адаптере и движке.

На инструментах нет большого вступительного экрана: форма доступна сразу, шапка появляется коротко с учётом reduced-motion. Общий контроллер переходов сохранён. Скрипты товарных сцен и ветки Design Lab загружаются только на соответствующих страницах. Управление поисковым диалогом входит в кешируемый скрипт шапки; поисковый движок остаётся отложенным. Новые клиентские зависимости не добавлены.

Общий результат содержит сводку, строки, колонки, пояснения и, при необходимости, дополнительные таблицы. Интерфейс, схема, CSV, текст запроса и печать используют этот результат. Формулы не повторяются в шаблоне документа.

## Единицы и версии

Поля геометрии принимают миллиметры; подпись единицы находится рядом с полем. Метраж в итогах переводится в метры, площадь — в м², объём — в м³, масса — в килограммы. Цена имеет выбранную единицу и хранится отдельно от неизвестной цены. Запятая и точка принимаются числовыми парсерами; пустое значение не преобразуется в ноль.

Для решений на границах геометрические движки используют целые тысячные миллиметра. Плитка использует удвоенную сетку, чтобы сохранить точный центр по плитке или шву. Масса, площадь и объём вычисляются до форматирования результата; округление отображения не является входом следующей формулы. Подробности ограничений и эталонов: `geometry-engines.md`, `cutting-engine.md`, `building.md` и тесты рядом с движками.

| Что версионируется | Текущее обозначение |
| --- | --- |
| Файл проекта | `format: "smu1-tools"`, `version: 1` |
| Методика каждого движка | `methodologyVersion: "1.0.0"` |
| Справочник уголков | `steel-angles: "1.0.0"` |
| Публичная структура каталога МАФ | `catalogue: "1.0.0"`; endpoint `version: "1.0.0"` |
| Ключ локальной папки | `smu1.tools.projects.v1` |

Версия структуры каталога не означает неизменность товара. МАФ сохраняет снимок выбранного изделия и сравнивает его с текущей опубликованной записью. Исчезнувшее или изменившееся изделие не подменяется автоматически.

## Контент, справочники и будущая админка

1. `src/content/tools/*.json` — названия, описание, SEO, порядок, аудитория, входы, текст методики, ограничения, пример, услуга, источники и гипотезы запросов. `id` и `slug` совпадают и ограничены семью стабильными адресами.
2. `src/content/tool-references/*.json` — табличные значения, единицы, версия, точное обозначение позиции и источник. `steel-angles.json` содержит три проверенные позиции ГОСТ 8509-93 и теоретическую плотность 7850 кг/м³.
3. `src/tools/calculations/*.mjs` — версионированные алгоритмы с независимыми эталонами. В контентных схемах нет поля для произвольной формулы.
4. Фотографии МАФ принадлежат существующей коллекции `products` и её responsive-media pipeline. Размерные рисунки инструментов создаёт код SVG; визуальный редактор не должен обещать редактирование формулы или результата посетителя.

Обе новые коллекции зарегистрированы в `src/content.config.ts` и строгих схемах `src/content-schemas.mjs`. Сторона локальной админки использует:

- `tools/admin-api/content-registry.mjs` — реестр коллекций, правила внутренних ссылок и HTTPS-источников;
- `content-json.mjs` — экспорт и импорт полного сайта, коллекции и страницы;
- `server.mjs`, `relation-graph.mjs` — директории, отношения, стабильные маршруты и резервирование `/instrumenty/`;
- `local-preview.mjs` — изолированный просмотр записи; строгим схемам инструментов не добавляется постороннее поле `isActive`;
- `publish-planner.mjs` — разрешённые контентные пути;
- `transaction-service.mjs` — HTML-проверка затронутой страницы, архива инструментов и страницы металла при изменении справочника;
- `content-validation.mjs` — изменение единиц, источника, плотности или табличных значений требует изменения версии справочника;
- `src/admin/metadata/content-coverage-registry.mjs`, `editor-fields.mjs`, `content-completeness.mjs` — назначение полей и честное описание границ редактирования.

Полный backup уже охватывает `src/content`; тесты подтверждают включение новых коллекций в переносимый архив. Публичная сборка не получает API, пароль или интерфейс локальной админки. Завершение её пользовательского интерфейса остаётся отдельным этапом.

## Каталог МАФ и изображения

`src/pages/instrumenty/catalog.json.ts` строится из `loadCatalogV2Snapshot().productRoutes`. Используются только опубликованные маршруты с `showInCatalog !== false`. Каждая запись содержит стабильный `id`, название, ссылку, режим и значение цены, валюту, характеристики, материалы и два разных поля изображения:

- `image` — исходный путь, используемый для определения изменения товара;
- `thumbnail` — оптимизированный вариант роли `card` из responsive-media manifest для интерфейса и печати.

Ссылки и пути endpoint хранятся без deployment base. Браузер добавляет текущий base. В стандартной и премиальной карточках товара обычная ссылка передаёт `#add=<product-id>` в МАФ. Это состояние приложения; после добавления изделия параметр потребляется. Для этого перехода вычислительный код на странице товара не загружается.

Проверка deploy-media учитывает точное назначение полей: только `products[].image` в `instrumenty/catalog.json` версии `1.0.0` может быть метаданными при наличии корректного пути миниатюры. Все миниатюры проверяются как ресурсы. Если миниатюра совпадает с оригиналом, оригинал остаётся необходимым. Отсутствующий файл останавливает очистку. Другие JSON-файлы исключения не получают.

## Локальные проекты и документы

Проект хранит независимый ID, инструмент, название, входы, версии методики и справочников, даты, признак примера и компактный исторический снимок. Снимок содержит использованные коэффициенты и сводку; он не заменяет проверку входов текущей методикой.

Папка ограничена 60 проектами, файл — 4 МиБ. Общая проверка JSON ограничивает глубину, длины и количество элементов, отвергает неизвестные поля и опасные имена свойств. Затем применяются ограничения конкретного инструмента. Импорт проверяется целиком до изменения папки. Импортированные результаты помечаются историческими; для актуального результата создаётся проверенная копия. При изменении версии прежний расчёт не пересчитывается молча.

Надпись «Сохранено на этом устройстве» появляется после успешной записи. При ошибке storage вычисления продолжаются, доступна выгрузка файла. Очистка браузера может удалить данные; перенос между preview и другим доменом выполняется файлом. Параметр `#project` ссылается только на локальную запись данного браузера и не является публичной ссылкой для обмена.

CSV имеет UTF-8 BOM, разделитель `;`, экранирование ячеек и защиту от формул. Дополнительные ведомости включаются в экспорт. Печать создаёт документ из того же результата и вызывает системную печать; PDF сохраняет сам браузер. Скопированный запрос, открытие почты и Telegram не считаются отправленной заявкой.

## Поиск, навигация и base

`v2TransitionRouting.mjs` описывает архив и семь страниц; `v2RouteRegistry.ts` загружает коллекцию инструментов. `withBase.ts` сохраняет работу на `/` и `/SMU1/`. `v2Routes.ts` оставляет ссылки инструментов публичными даже из дизайн-лаборатории, где отдельные копии этих страниц не создаются.

`search-index.json.ts` передаёт инструменты в `publicSearchIndex.mjs`. Тип `tool` добавлен в генератор, клиентскую проверку `public-search.mjs` и подпись «Инструмент». Поиск использует опубликованное описание и группы запросов. Один пункт раздела добавлен в существующие меню компании, мобильную навигацию и футер.

Публичный HTML содержит только стабильные страницы, без сохранённых пользовательских расчётов. В production sitemap исключаются JSON endpoint. Preview сохраняет `noindex` и отключённую аналитику; включение production выполняется отдельным этапом.

## Аналитика и конфиденциальность

Цели: `tool_start`, `tool_result`, `tool_export`, `tool_service`, `tool_contact_start`. В параметрах цели передаётся только стабильный ID инструмента. Размеры, суммы, адреса, произвольный текст, имена проектов и файлы в параметры событий не включаются. Начало и успешный результат не отправляются на каждое нажатие клавиши.

Вызовы разрешены только для production при наличии состояния существующего счётчика Метрики. Статус отправки заявки не выводится на основании события или открытия внешнего приложения.

Отдельный обязательный барьер — защита пользовательского содержимого от существующего Вебвизора. Нельзя считать безопасный payload цели достаточным, если записываются поля или результаты. Контейнер приложения и создаваемый печатный документ получают `ym-hide-content`; поля, поиск МАФ, название проекта и резервное поле копирования — `ym-disable-keys`. Маски действуют и при переходе из уже записываемой страницы сайта. Назначение классов описано в [официальных настройках Вебвизора](https://yandex.ru/support/metrica/ru/webvisor/settings) и [правилах HTML-разметки Метрики](https://yandex.ru/support/metrica/ru/code/html-markup).

Перед отложенной инициализацией `PublicV2Layout.astro` удаляет query и hash только у адресов раздела инструментов в `url` и `referrer`, включая обе конфигурации `/instrumenty/` и `/SMU1/instrumenty/`. Проверяется актуальный адрес в момент загрузки, поскольку переход мог случиться за время задержки. Если счётчик впервые загружается на инструменте, Вебвизор выключается; на остальных страницах существующая конфигурация сохраняется. Дополнительных SPA `hit` в текущем коде нет. Новые способы отправки аналитики должны использовать такое же ограничение адреса. `tool-analytics-privacy.test.mjs` исполняет реальный inline-инициализатор в тестовом окружении, проверяет созданные поля и печатный документ. H6 дополнительно проверяет маски в фактическом DOM каждого инструмента.

## Что измерять после запуска

До запуска частотности Wordstat не получены; группы запросов в контенте — гипотезы. Результат разработки не доказывает рост позиций или посещаемости.

После отдельного включения production:

1. Проверить robots, canonical, sitemap, обход и индексирование семи адресов в Яндекс Вебмастере и Search Console.
2. Собирать показы, запросы, клики и CTR по странице, региону, устройству и датам. Первый период после индексирования служит исходной точкой; сравнивать сопоставимые периоды.
3. Оценивать переходы из поиска, начало работы, успешный результат, экспорт и переход к услуге по агрегированным событиям.
4. Реальные содержательные обращения учитывать отдельно по каналу связи. Событие `tool_contact_start` показывает намерение, а не доставленную заявку.
5. Проверять, какие задачи доводят посетителей до пригодной ведомости и обращения; исправлять содержание и интерфейс по наблюдаемым затруднениям. Не создавать дубли страниц под перестановки слов и города.

Основные поисковые источники и ограниченное исследование находятся в `research.md`.

## Итоговый QA и проверка публикации

`npm run qa:final` объединяет проверку Astro, тесты инструментов и админки, H6-контракты, сборку, exact-проверку, performance, статические ссылки/ресурсы, поиск, подготовку deploy-артефакта, браузерные и motion-проверки, route passport, public/admin actions, privacy, backup/restore и согласование всех доказательств.

Перед запуском исходники должны быть зафиксированы. Изменённые `dist`, `.astro` и `.admin-runtime` исключаются из проверки чистоты исходников; остальные незавершённые изменения блокируют exact/evidence QA. После изменения кода необходимо заново собрать и проверить соответствующий артефакт. Нельзя подменять финальные доказательства запуском с `--allow-stale-dist` или сокращённым списком маршрутов.

Окружение локального preview QA:

```powershell
$env:DEPLOY_TARGET = 'test'
$env:PRODUCTION_DEPLOY_ENABLED = 'false'
$env:SITE_URL = 'https://koleaw.github.io'
$env:TEST_SITE_URL = 'https://koleaw.github.io'
$env:BASE_PATH = '/SMU1'
$env:CHROME_PATH = 'C:/Program Files/Google/Chrome/Application/chrome.exe'
npm run qa:final
```

Требуются зависимости из lockfile, Git и Chromium с доступным DevTools Protocol. Node должен поддерживать глобальный WebSocket; CI использует Node 22.12.0. Для admin browser QA временная директория должна находиться вне репозитория и на том же диске Windows; текущий default — `E:/CodexTemp/smu1-admin-browser`. Backup drill сам проверяет место по размеру содержимого: минимум 1 ГиБ либо `3,25 × managedBytes + 256 МиБ`, если это больше. Локальные тестовые серверы запускаются на loopback; production-разрешения для QA не нужны.

Ожидаемый полный артефакт содержит 237 HTML: 119 публичных, 112 дизайн-лаборатории и 6 совместимых закрытых страниц админки. Среди публичных — 115 canonical, 3 перенаправления и 404. Статический QA принимает `#add` только для существующего опубликованного товара, а H6 проверяет фактическое добавление в ведомость. Произвольные hashes продолжают проверяться как якоря.

При мониторинге GitHub Actions смотреть запуск конкретного проверенного SHA, все обязательные jobs и итоговую публикацию. CLI `gh` необязателен: доступны GitHub connector и публичные REST endpoints runs/jobs/artifacts. Успешная сборка сама по себе не означает публикацию. Действующий workflow разрешает Pages только из `preview`, требует равенства `v4-product-final-candidate == preview == tested SHA` перед загрузкой и непосредственно перед deployment. После публикации `https://koleaw.github.io/SMU1/_release/identity.json` должен содержать тот же `testedCommitSha`; затем проверяются страницы и ресурсы на публичном адресе. Main и production-домен этот этап не меняет.

### Воспроизводимая среда публичного обхода

Jobs `public-runtime`, `public-inputs`, `public-actions`, `public-evidence`, `release` и `resume-evidence` используют официальный образ `mcr.microsoft.com/playwright:v1.63.0-noble@sha256:eff16c30e6f3f4af0a03fa4b706120d5e9b0891c344a27d64559aff5900a4a27`. Digest OCI manifest проверен по байтам ответа Microsoft Container Registry. Браузер запускается из `/ms-playwright/chromium-1243/chrome-linux64/chrome`; preflight требует фактическую версию Chromium 153.0.8010.12 и marker контейнера. Версия Node остаётся 22.12.0 через setup-node.

Это устраняет несовпадение пользовательских библиотек, шрифтов и браузера при поэтапном обновлении hosted runners GitHub. Ключ evidence сохраняет все прежние составляющие и реальную версию браузера. В контейнере идентификатор образа — закреплённый digest; вне контейнера сохраняется исходный ImageVersion/RUNNER_OS. Неверный образ, marker или путь браузера блокирует приёмку. При несовпадении входного ключа сохраняется диагностический файл, но обход не продолжается. Клиентские npm-зависимости не добавляются.

Источники: [Playwright Docker](https://playwright.dev/docs/next/docker), [официальный Dockerfile 1.63.0](https://github.com/microsoft/playwright/blob/v1.63.0/utils/docker/Dockerfile.noble), [закреплённые версии браузеров](https://github.com/microsoft/playwright/blob/v1.63.0/packages/playwright-core/browsers.json).
