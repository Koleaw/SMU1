# Pages CMS выведен из эксплуатации

Начиная с локальной админки H6, Pages CMS не является редактором сайта СМУ-1. Корневой файл `.pages.yml` намеренно удалён, поэтому подключённый Pages CMS не должен распознавать этот репозиторий как активную CMS-конфигурацию.

## Почему конфигурация удалена

Старая схема была неполной и опасной как второй writer:

- охватывала лишь часть актуальных коллекций и полей;
- писала JSON напрямую, обходя revision/OCC, relation checks и crash-recoverable транзакции;
- обходила браузерные черновики, историю и управляемое восстановление;
- загружала файлы непосредственно в `public/uploads`, минуя staging, content-addressed naming и server-side media validation;
- разрешала новые SVG, хотя H6 upload policy их запрещает;
- не обеспечивала exact-SHA gates и atomic candidate + preview publish;
- могла конфликтовать с локальной админкой и терять изменения при двух параллельных источниках записи.

Удаление `.pages.yml` не удаляет контент. Source of truth по-прежнему находится в `src/content` и зарегистрированных `src/data` singletons.

## Чем пользоваться сейчас

Владелец запускает локальную админку:

```bash
npm run admin
```

Рабочий URL: `http://127.0.0.1:4321/admin/`.

Первичную настройку выполняет разработчик через `npm ci` и `npm run admin:setup`. Практическая инструкция: [ADMIN_LOCAL_STAGE1.md](ADMIN_LOCAL_STAGE1.md).

## Запрет на скрытое повторное включение

Не добавляйте `.pages.yml`, `.pages.yaml` или эквивалентную CMS-конфигурацию «временно». Возврат облачного редактора потребует отдельного архитектурного этапа: единый transaction API, роли, audit log, media policy, conflict resolution, backup/restore и тот же publish contract. До такого review локальная админка остаётся единственным поддерживаемым writer.

Этот файл сохранён только как migration note, чтобы старые ссылки не подталкивали к повторному включению Pages CMS.
